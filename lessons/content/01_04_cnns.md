## Learning outcomes

After this lesson you should be able to:

- explain why **fully connected layers alone** are impractical for image recognition;
- explain why convolution is a good **prior** for image processing;
- interpret a **convolution as a neural network** with local connections and shared weights;
- describe the **structure of a CNN** and name what each layer type contributes;
- explain what **features** convolution layers learn and how they change with depth;
- calculate the **receptive field** of a neuron;
- explain **translation invariance** and where it comes from;
- read off the shapes and parameter counts of a complete network such as **LeNet-5**.

## Introduction

Convolutional layers are the main building block of deep neural networks for imaging. They sit at the front of the network and perform its key function: detecting image features, both simple and complex. A deep network usually also contains fully connected layers with softmax activation at the end, to produce the final class probabilities.

This lesson answers two questions — why convolution is used in neural networks for images, and how a convolution operation can be interpreted as a neural network — and then looks at a complete example.

## Processing images with fully connected layers

The simplest but naïve approach is to use a traditional fully connected network. The image must first be rearranged into a vector: a $4 \times 4$ image becomes a vector of 16 values, which can then be connected to a layer of neurons.

{{fig fc_on_images}}

For a $4 \times 4$ image and two neurons this costs 34 parameters, which is nothing. But a more typical $256 \times 256$ image gives a vector of 65,536 values, and connecting that to even a small layer of 100 neurons needs **6,553,700 parameters** — in the first layer alone. Directly processing medium or large images with fully connected networks consumes far too much memory and computation to be practical.

There is a second problem, and it is arguably the more serious one. Flattening destroys the spatial arrangement. Two pixels that sit side by side in the image end up as two arbitrary entries of a long vector, and the dense layer has no reason to treat them as related.

## Why convolution

Convolution addresses both problems at once.

A key property of convolution is that it operates only on small $n \times n$ regions of the image rather than on the whole image at once, and it applies **the same filter to every region**. The number of parameters equals the size of the filter — 9 for a $3 \times 3$ kernel — no matter how large the image is. Compare that with the fully connected approach, which considers all pixels together and uses a number of parameters that grows with the image.

Including convolution in the architecture is a **prior**: we are building in our existing knowledge that image processing is efficiently done with local filters. The crucial difference from classical image processing is that here the **kernel parameters are learned during training**, rather than being specified in advance.

## Convolution as a neural network

Consider convolving a $3 \times 3$ image with a $2 \times 2$ kernel, valid padding. There are four positions the kernel can visit, giving a $2 \times 2$ output.

Each position can be interpreted as a **neuron**. Draw the image pixels as a column vector; the multiply-and-sum the kernel performs at one position is exactly the weighted sum inside a neuron. Adding a bias term and an activation function makes it a neuron in the full sense.

{{fig conv_as_nn}}

The result looks like the fully connected networks of Lesson 1.2, but with two decisive differences:

- the network is **not fully connected** — each neuron sees only the pixels under the kernel, which saves computation;
- every neuron uses **the same weights**, which saves memory.

In a real CNN a bias parameter is added at each neuron, and since the neurons share the kernel they also share that single bias.

## The structure of a CNN

{{fig cnn_structure}}

Rather than drawing feature maps, a network is often shown as a sequence of operations, from which the feature-map sizes can be inferred. Convolution layers come first, usually with `same` padding so the spatial size is preserved, and are **stacked** to make the network deeper, which helps it learn complex features. The **activation** is drawn as its own layer; it is good practice to show it explicitly, because in modern CNNs a convolution layer sometimes appears without one.

**Pooling** layers summarise features and reduce the spatial size, which reduces computation. Note the common pattern: as pooling reduces the spatial size, the number of kernels is increased to compensate.

Finally, to turn the last feature map into a class prediction, a **flatten** layer converts it to a vector, which feeds a **dense** layer with one neuron per class and a softmax activation.

## Learned features

During training the kernel parameters are learned, so a convolution layer ends up responding to whatever features are useful for the task. It helps to think of the layer as cross-correlating the image with those learned features: the response is large where the image resembles the kernel.

{{fig learned_features}}

Early convolution layers reliably learn simple things — lines, edges, colour boundaries. Deeper layers learn much more complex features, which can resemble object parts and eventually entire objects. The pattern of responses in the final feature map is what the classifier stage reads to produce a class probability.

## Receptive field

The **receptive field** of a neuron is the size of the region in the input that it can see, or respond to. It matters for recognition: the receptive field must be large enough to cover the objects of interest.

It is determined by the preceding convolution and pooling layers, and is found by working **backwards** from the neuron using

$$r_{l-1} = s_l \cdot r_l + (k_l - s_l), \tag{1}$$

starting from $r = 1$ at the deepest layer.

{{fig receptive_field}}

Notice the role of stride. A pooling layer with stride 2 does not just add to the receptive field, it **multiplies** everything accumulated so far, which is why receptive fields grow quickly once a network starts downsampling. As we go deeper into a network the receptive field generally increases.

{{example rfield seed=4}}

## Translation invariance

**Translation invariance** is the ability of a network to give the same response wherever in the image an object is located — if the subject is a cat, we want the same classification whether the cat is top-left or bottom-right.

Convolution layers build this in automatically, because the same feature detection is applied everywhere in the image. Pooling contributes as well.

{{fig translation_invariance}}

In the figure a max pooling window of size 3 is applied to 1D data. When the data is shifted by one position, the peak is still captured by the same pooling window and is still the maximum value in it, so the pooled output is unchanged. This invariance to small translations helps the network identify objects that have shifted position.

It is worth being precise about what pooling buys, because it is easy to overclaim. The invariance is **partial**: it holds for shifts small enough that the feature stays inside its pooling window. Shift the peak far enough to cross into the next window and the output does change, as the figure's caption shows. Tolerance to *arbitrary* translation comes from the convolution layers applying the same kernel everywhere, not from pooling.

## A simple CNN: LeNet-5

We now have everything needed to read a complete network. **LeNet-5** was developed in 1998 for handwritten digit recognition on the MNIST dataset, and operates on small $32 \times 32$ greyscale images.

{{fig lenet5}}

It is not deep by modern standards: two convolution layers, two pooling layers and three fully connected layers. Trace the shapes through it and notice how the rules from the previous lessons pin everything down.

- The first convolution uses $5 \times 5$ kernels and produces **6** feature maps of size $28 \times 28$, so there must be 6 kernels. They have **1** channel each, because the input is greyscale.
- Average pooling reduces $28 \times 28$ to $14 \times 14$, implying a stride of 2. The **number of channels is unchanged** by pooling.
- The second convolution produces **16** feature maps, so there are 16 kernels, and they must have **6** channels to match the 6 maps arriving from the previous stage.
- Pooling again gives $5 \times 5 \times 16$. A flatten operation, not drawn, turns this into a vector of 400.
- Three dense layers of 120, 84 and 10 neurons follow. The last has 10 neurons because MNIST has 10 classes, with softmax so a probability per class can be output.

{{example conv_arith2 seed=5}}

Look at where the parameters are. The convolution layers hold only a few thousand; the three dense layers hold the overwhelming majority — the same lopsidedness Lesson 1.2 predicted. Section 2 returns to this, because getting rid of those large dense layers is one of the main architectural advances of the last decade.

Finally, a word of caution: there is no rule for choosing the number of convolution layers, kernels, pooling layers or dense neurons for a given application. Finding the right level of complexity takes a designer many trial-and-error attempts.
