## Learning outcomes

On completion of this lesson the student should be able to:

- explain why **fully connected layers alone** are impractical for image recognition;
- explain why convolution is a good **prior** for image processing;
- interpret a **convolution as a neural network** with local connections and shared weights;
- describe the **structure of a CNN** and the function of each layer type;
- explain the **features** learned by convolution layers and how they change with depth;
- calculate the **receptive field** of a neuron;
- explain **translation invariance** and how it is obtained;
- determine the shapes and parameter counts of a complete network such as **LeNet-5**.

## Introduction

Convolutional layers are the main building block of deep neural networks for imaging. They are located at the front of the network and perform its key function, the detection of image features, both simple and complex. A deep network usually also contains fully connected layers with softmax activation at the end, to provide the final class probabilities.

In this lesson two questions are addressed: why convolution is used in neural networks for images, and how a convolution operation can be interpreted as a neural network. An example of a simple convolutional neural network is then described.

## Processing images with fully connected layers

The simplest, but naïve, approach is to use a traditional fully connected network. The image must first be rearranged into a vector: a $4 \times 4$ image becomes a vector of 16 values, which can then be connected to a layer of neurons.

{{fig fc_on_images}}

For a $4 \times 4$ image and two neurons, 34 parameters are required. For a more typical $256 \times 256$ image, however, the vector has 65,536 values, and when it is connected to even a small layer of 100 neurons, **6,553,700 parameters** are required in the first layer alone. Directly processing medium or large images with fully connected networks therefore requires too much memory and computation to be practical.

A further problem is that the spatial arrangement of the pixels is lost when the image is flattened. Two neighbouring pixels in the image become two unrelated entries in a long vector, and no relationship between them is assumed by the dense layer.

## Why convolution

Both of these problems are addressed by convolution.

A key property of convolution is that it operates only on small $n \times n$ regions of the image rather than on the whole image, and **the same filter is applied to every region**. The number of parameters is equal to the size of the filter (9 for a $3 \times 3$ kernel), regardless of the size of the image. In contrast, in the fully connected approach all pixels are considered together, and the number of parameters increases with the size of the image.

The inclusion of convolution in the architecture can be considered a **prior**: existing knowledge that image processing can be performed efficiently with local filters is built into the network. The key difference from classical image processing is that the **kernel parameters are learned during training**, rather than being specified in advance.

## Convolution as a neural network

The convolution of a $3 \times 3$ image with a $2 \times 2$ kernel, with valid padding, is considered. There are four positions the kernel can occupy, giving a $2 \times 2$ output.

Each position can be interpreted as a **neuron**. If the image pixels are drawn as a column vector, the multiply-and-sum performed by the kernel at one position is the same as the weighted sum in a neuron. When a bias term and an activation function are added, the operation is mathematically the same as a neuron.

{{fig conv_as_nn}}

The resulting network is similar to the fully connected networks of Lesson 1.2, with two important differences:

- the network is **not fully connected**, as each neuron is connected only to the pixels under the kernel, which saves computation;
- **the same weights** are used by every neuron, which saves memory.

In a CNN a bias parameter is added at each neuron, and as the neurons share the same kernel, they also share a single bias.

## The structure of a CNN

{{fig cnn_structure}}

Rather than the feature maps being drawn, a network is often represented as a sequence of operations, from which the sizes of the feature maps can be inferred. Convolution layers are used first, usually with `same` padding so that the spatial size is preserved, and they are **stacked** to produce a deeper network, which helps the network to learn complex features. The **activation** is shown as a separate layer. It is good practice to show the activation explicitly, as in modern CNNs a convolution layer may appear without an activation in certain circumstances.

**Pooling** layers summarise features and reduce the spatial size, which reduces computation. A common pattern can be seen in the figure: the number of kernels is increased as the spatial size is reduced by pooling.

Finally, to obtain a class prediction from the last feature map, a **flatten** layer is used to convert the feature map to a vector. This vector is applied to a **dense** layer with one neuron per class and a softmax activation.

## Learned features

The kernel parameters are learned during training, so each convolution layer responds to the features that are useful for the task. It may be helpful to consider the layer as performing cross-correlation between the image and the learned features, so that the response is large where the image resembles the kernel.

{{fig learned_features}}

Simple features such as lines, edges and colour boundaries are learned in the early convolution layers. Much more complex features, which can resemble parts of objects and eventually entire objects, are learned in the deeper layers. The responses in the final feature map are interpreted by the classifier stage, and a class probability is output.

## Receptive field

The **receptive field** of a neuron is the size of the region in the input that the neuron can view, or respond to. The receptive field is important for recognition, as it must be large enough to cover the objects of interest.

The receptive field is determined by the preceding convolution and pooling layers, and is calculated by working **backwards** from the neuron using

$$r_{l-1} = s_l \cdot r_l + (k_l - s_l), \tag{1}$$

starting from $r = 1$ at the deepest layer.

{{fig receptive_field}}

The effect of stride should be noted. A pooling layer with stride 2 multiplies the receptive field accumulated in the layers after it, rather than simply adding to it, and so the receptive field increases rapidly once downsampling is applied in a network. In general, the receptive field increases with depth.

{{example rfield seed=4}}

## Translation invariance

**Translation invariance** is the ability of a network to give the same response regardless of where in the image an object is located. For example, if the subject of an image is a cat, the same classification is required whether the cat is at the top left or the bottom right of the image.

Translation invariance is built into convolution layers, as the same feature detection is applied everywhere in the image. Pooling layers also contribute to translation invariance.

{{fig translation_invariance}}

In the figure, a max pooling window of size 3 is applied to 1D data. When the data is shifted by one position, the peak is still captured by the same pooling window and is still the maximum value in that window, so the pooled output is unchanged. This invariance to small translations may help the network to identify objects that have shifted position.

The invariance provided by pooling is **partial**. It applies only to shifts small enough that the feature remains within its pooling window. When the peak is shifted into the next window, the output changes, as described in the figure caption. Tolerance to larger translations is provided by the convolution layers, in which the same kernel is applied at every position, rather than by pooling.

## A simple CNN: LeNet-5

The concepts covered so far are sufficient to describe a complete network. **LeNet-5** was developed in 1998 for handwritten digit recognition on the MNIST dataset, and operates on small $32 \times 32$ greyscale images.

{{fig lenet5}}

The network is not deep by modern standards: it has two convolution layers, two pooling layers and three fully connected layers. The shapes throughout the network can be determined with the rules from the previous lessons.

- The first convolution uses $5 \times 5$ kernels and produces **6** feature maps of size $28 \times 28$, so there must be 6 kernels. Each kernel has **1** channel, as the input is greyscale.
- Average pooling reduces the size from $28 \times 28$ to $14 \times 14$, which indicates a stride of 2. The **number of channels is unchanged** by pooling.
- The second convolution produces **16** feature maps, so there are 16 kernels, and each must have **6** channels to match the 6 feature maps from the previous stage.
- A second pooling stage gives $5 \times 5 \times 16$. A flatten operation converts this to a vector of 400 values.
- Three dense layers of 120, 84 and 10 neurons follow. The last layer has 10 neurons, as there are 10 classes in MNIST, and softmax activation is applied so that a probability is output for each class.

{{example conv_arith2 seed=5}}

It can be seen that the convolution layers contain only a few thousand parameters, while the large majority of the parameters are in the three dense layers, as predicted in Lesson 1.2. This is discussed further in Section 2, as the removal of large dense layers is one of the main architectural advances of the last decade.

Finally, there is no rule for choosing the number of convolution layers, kernels, pooling layers or dense neurons for a given application. Many trial-and-error attempts are usually required to find the appropriate level of complexity.
