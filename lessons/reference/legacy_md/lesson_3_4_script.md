# Object Detection (Part B): Single Stage Object Detection 

## Slide 1: Title Slide 

<mark>In this second part of the lesson on object detection with deep convolutional neural networks, we will focus on so-called single stage object detectors. In part A of this lesson, we focused on the RCNN family of detectors with region proposals. Region proposal, or two stage detectors as they are also known, are considered to be the most accurate object detectors, but are also computationally expensive. In this part B of the lesson, we will focus on more simple single stage object detectors, which are still based on Deep CNN architectures. These less computationally expensive and faster networks are often useful for mobile and embedded applications</mark> 

## Slide 2: Principles of Single Stage Detectors 

<mark>The naïve approach to single stage object detection uses an Image Classifier deep convolutional neural network as a sliding window detector. As image classifiers are trained on fixed image sizes e.g. 224 x 224 pixels, we could apply the detector at overlapping windows in a large high resolution image. The size of objects detected in the image would need to correspond to the input window size. Large objects greater than the window size could be detected by successively reducing the size of the image (creating an image pyramid) and applying the detector in a sliding window fashion over all the images in the pyramid. While this approach is technically feasible and is how classical object detectors work, it is very computationally inefficient as the DCNN is being iterated possibly 1000’s of times to find an object in an image. The approach was acceptable for classical detectors as they were computationally lightweight and multiple iterations for a single image was acceptable.</mark> 

<mark>The correct approach to building a deep learning based object detector is to use information about the entire image that is available in the convolutional part of the image classifier. The feature maps output by the convolution operations contain both spatial position and semantic information about objects in an image. Figure (a) shows an image of a car input to a network trained to perform image classification, figure (b) shows the activation response of a single deep feature map to the image. It is clear that activation is maximised for particular image features in the spatial region around the object. The activation location gives Course information about the object location. Fine information about the spatial extent of an object may be obtained by processing depthwise channel information. Unlike the naïve sliding window approach, we only need to process each image once through the convolutional layers of an image classifier network to get all the information required to predict object locations. This is obviously far more computationally efficient. We will later discuss how we successfully deal with detecting objects of different sizes and how to avoid image pyramids with this approach.</mark> 

## Slide 3: Object Detection System 

<mark>As we have mentioned on the previous slide we can obtain positional information about objects from the output feature maps of a pretrained image classification network. In figure (a) we show how we can construct a basic single stage object detection system. We can accurately obtain bounding boxes of objects by adding a so called “Prediction head”, which is itself a small convolutional neural network usually with a kernel size of 3 x 3, to the output feature map of a pretrained image classifier network. As shown in figure (b) as the convolution operation moves over the</mark> 

<mark>output feature map, it can firstly predict a confidence probability value, which indicates if there is actually object information present in the current 3 x 3 region of the feature map. The prediction head also simultaneously predicts the class and bounding box of the object. The individual pixels or cells in the feature maps have a large receptive field and therefore capture the extent of the object in the original image. This fine position information is stored depthwise in the feature map. We therefore only need to use small kernels in the prediction head and don’t need to combine information from the entire feature map to predict object positions. A final point that we note is that the bounding prediction produced by the predictor head is only relative to the current position of the kernel in the feature map. Therefore the prediction must be corrected by the coarse position to obtain coordinates in the actual image.</mark> 

## Slide 4: Object Detection Output and Training 

<mark>As we have seen on the last slide, the prediction head operates in a convolutional manner over the output feature map from the image classification network, and can produce predictions for bounding boxes, object confidence and class. All these predictions are output as a vector shown in figure (b). In the simplest case where we attempt to predict one bounding box, the vector will contain 4 coordinate values corresponding to the bounding box, a confidence value indicting the probability of an object and also a set of probabilities (usually a softmax output) corresponding to the class of the object. In the example shown we have two predictions for bounding boxes shown in the vector. Prediction of multiple boxes is quite common in object detection systems, it is a consequence of using so called “anchor boxes” in the system. The anchor boxes act as priors with different shapes and aspect ratios helping to detect different shaped objects and improving training stability along with other advantages, we will discuss anchor boxes more on the next slide. The confidence value does not always have to be predicted as an independent quantity. Instead a background class can be added to the classification categories. This may lead to class imbalance during training as the background class will dominate.  Usually class probability is predicted once for the entire cell, although class can be predicted for each anchor box separately at the cost of a larger network.</mark> 

<mark>Training an object detection system poses a more difficult problem than training an image classifier, as the ground truth is no longer a single label for each image. Instead there are multiple ground truths corresponding to the particular object size and class at different locations in the image. When training the prediction head network it is necessary to indicate which feature map cells contain valid objects and assign the correct ground truth for the relevant object to that cell. We can also use the anchor boxes as part of the process to indicate which feature map cells contain ground truth objects. If the anchor box overlaps with the ground truth box above a certain IoU threshold, then the anchor is selected for prediction. As we will discuss in the next slides the prediction head predicts the offset and scale of the anchor from the ground truth. Using anchor based prediction involves a lot of additional computation during training as the IoU of each anchor in each cell must be obtained against each object in the image. However computing this may allow multiple anchors in the same cell or neighbouring cells predict bounding boxes. This effectively increases the number of positive examples for training. When it comes to training confidence, additional positive examples are useful as it helps reduce the imbalance between positive and negative examples, which we will talk more about in a later slide.</mark> 

## Slide 5: Anchor Boxes 

<mark>In the previous slide we discussed using anchor boxes to help determine where to make predictions about the presence of objects. Anchor boxes are widely used in many object detectors and have a</mark> 

<mark>number of advantages. Anchor boxes act as a prior, we can predict the offset and scale of the anchor from the ground truth. We will detail the prediction of bounding box coordinates on the next slide. This approach of using anchor boxes may produce faster training convergence as some of the anchors will already be close to the size and shape of objects in the dataset. Typically the choice of anchor box dimensions will be set a priori depending on the types of objects in the dataset. This can lead to some bias towards particular objects in the object detector, which may be more noticeable if used on a wider set of images after training. Using anchor boxes can cause the object detector to work well for large objects with wide aspect ratios such as aeroplanes, but there may be problems with smaller objects. Another advantage of anchor boxes is that a set of anchor boxes can be predicted at each feature map cell. This not only allows the appropriate anchor to be selected, but multiple anchors can be selected if overlapping objects are present in the same location. The figure (b) on the slide shows examples of available anchor boxes in two cells, that could be used to predict ground truth in figure (a). As mentioned on the previous slide, if the IoU of any anchor with any ground truth box is greater than a threshold then the anchor is selected as a positive prediction and can be used to predict bounding boxes. These positive predictions are also used for confidence prediction and all cases where the loU was less than a threshold are used for negative confidence prediction, leading to an imbalance as there are always significantly more negative predictions.</mark>

## Slide 9: Scale Problem in Single Stage Object Detectors. 

<mark>So far we have discussed single stage object detectors that use a single output feature map from the image classifier to make predictions about object locations. The output feature map used is usually the last convolution layer of the image classifier. This feature map typically has a course spatial resolution and a wide receptive field and will usually only be able to be successfully trained to localise large objects. The simplest approach detect smaller objects is to increase their apparent size in the image by increasing the image resolution.  An image pyramid could be used with this basic fixed scale detector at the cost of extra computation to help pick up objects at different scales. A more computationally efficient approach is to use feature maps from the image classifier network at different scales. As shown in the images (a) and (b) on the slide we can detect objects at different scales in different feature maps. Larger objects will be detected in coarse feature maps with large receptive fields and smaller objects can be detected in fine feature maps which will have smaller receptive fields. Each of the feature maps to be used will have a nominal scale assigned to it, the anchor boxes will be set to a size that allows detection of objects in a range around this nominal scale.</mark> 

<mark>If we attempt to predict objects from the fine feature maps of the image classifier, the detection performance may not be as good as expected. The convolution filters in these fine feature maps may extract more generic features from images and at not contain explicit semantic information about smaller objects. The extracted features may belong to several different types of objects or background structures making detection of the extent of objects more difficult in fine feature maps. As we will see in the next two slides the single shot detector and the Feature pyramid network objects detectors take approaches to ensure semantic information in fine feature maps for prediction.</mark> 

## Slide 10: SSD “Single Shot multibox Detector” 

<mark>As mentioned on the last slide, we want to use feature maps at different scales to successfully predict both large and small objects. The SSD is a well known object detector that uses multi scale feature maps. As shown in figure (a), SSD is based on the VGG-16 network. The SSD network does not use the fine feature maps of the VGG-16 network as these feature maps do not contain semantic information about small objects. To get around this problem, the final convolutional output feature map of VGG-16: the conv_5_3 layer, which contains semantic information is used as the starting layer to create a series of multiscale maps. An increased input image size is used to allow enough spatial resolution for downsampling between the multi-scale maps. Predictions of bounding boxes</mark> 

<mark>and classes are determined at each of the multiscale feature maps using 3 x 3 convolutions. SSD uses the concept of anchor boxes like many object detection systems.</mark> 

## Slide 11: Feature Pyramid Networks. 

The feature pyramid network is another very well known approach to building single stage object detectors. Similar to the SSD network, FPN is also an approach with multi-scale feature maps. The FPN also uses a pre-trained image classifier as the backbone, this is ResNet 50 in this case. The FPN network uses a different approach to dealing with the problem of poor semantic information in the fine feature maps of the image classifier network. As shown in figure (a), the FPN uses a parallel pyramid, which generates feature maps at different scales. This pyramid importantly uses semantic information from the output of the image classifier (that is the last feature map on the left) as the starting feature map for the pyramid. This starting feature map is upsampled and combined with fine feature information. Figure (b) shows a more detailed construction of the pyramid. It is noted that a 5 layer pyramid is created with additional downsampling for layers P6 & P7. A common prediction head is used for all feature maps of the pyramid, so all feature maps must have the same depth.  The FPN yields good performance for smaller objects, it can be trained on input images of different sizes, with larger images giving better performance on small objects at the cost of computation. The FPN is widely adopted approach and is used in many modern object detectors.
