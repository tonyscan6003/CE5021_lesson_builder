# Architectures for Image Classification 

## Slide 1: Title Slide 

<mark>In this video, we will introduce some key neural network architectures for image classification, including AlexNet, VGG and Inception.</mark> 

## Slide 2: AlexNet 

<mark>The AlexNet architecture was the first neural network to win the large scale image recognition challenge on the ImageNet dataset. This win proved that with large amounts of training data, large neural networks could learn features from images and surpass all the classical hand engineered computer vision approaches. The architecture shown on the slide is a single GPU version of AlexNet. The  original Alexnet had to be split over two GPUs, which was due to the memory limitations of the GPU technology available to the authors. The path on each GPU contains parallel convolution blocks, pooling was used to recombine the two paths after convolution. This structure is similar to the LeNet-5 we saw previously. Again, it contains 5 convolution, 3 pooling and 3 fully connected layers with a softmax activation in the last layer. As AlexNet was trained using the IMAGENET dataset, which has 1000 classes, AlexNet outputs 1000 class probabilities. The key difference between AlexNet and the earlier LeNet5 is the scale of the network. Compared to LeNet-5, the image size is quite large at 224 x 224. The first convolution layer therefore uses large kernels of size 11 x 11. The number of kernels is much greater than LeNet5 with 96 output feature maps corresponding to the same number of kernels. As we go deeper into the network, the number of feature maps increases to maximum of 384. The feature map spatial size is reduced by each of the pooling layers. Generally, as the number of feature maps increases, the spatial size of the feature maps is decreased. This balances the number of parameters in each layer. Also, smaller kernels are used in deeper layers. Like LeNet5, AlexNet has a number of fully connected layers at the end that effectively act as a classifier. In the AlexNet network, there are a very large number of neurons in these layers. As we will see in the next slide, these fully connected layers contain the majority of the parameters in the network.  AlexNet also adopted rectified linear unit (ReLU) activations, which help with training the network, as the traditional sigmoid and hyperbolic tangent (tanh) functions can tend to saturate and lead to vanishing gradients during training. AlexNet also used dropout regularisation with the fully connected layers and data augmentation during training again to help avoid overfitting.</mark> 

## Slide 3: AlexNet Computation and Memory Requirements 

<mark>As we saw in the last slide, the AlexNet neural network has a larger size and many more output feature maps than LeNet5. The fully connected layers also contain significantly more neurons. On this slide, we will briefly look at the computational and memory requirements of AlexNet. These are summarised in figure (a). The memory requirements are determined by counting the number of parameters in each layer. For a convolutional layer, the number of parameters in each of the kernels of the layer is summed to give the total number of parameters for that layer. For the fully connected layers, each neuron is connected to all the inputs. Therefore, the total number of weights will be the same as the number of inputs multiplied by the numbers of neurons. As we can see in the figure, the memory requirements of the convolutional layers is in the range of tens to hundreds of thousands of parameters. However, the number of parameters in the fully connected layers is of the order of tens of millions. The maximum computation rate the GPU can achieve with fully connected layers is often limited by memory bandwidth, not the available computation speed and this can cause training to proceed more slowly. The total number of parameters in AlexNet is approximately 60 million. If we are using a 16bit precision device to train or test AlexNet, then the memory requirement to store the</mark> 

<mark>AlexNet network is 120MB. This is clearly a very large value, greater than the memory available in many mobile and embedded devices. As we can see on the slide, the computational requirements of AlexNet are dominated by the convolutional layers. Convolution is a very computationally expensive operation. The stepping of the kernel around the input image leads to a very large number of multiplication operations. However, computation with convolutional layers is not limited by memory bandwidth, like fully connected layers and the full computational performance of a GPU can be used. The total number of floating point operations in AlexNet is 600 million. A lower end GPU that can process AlexNet at 600GFLOPS can pass 1000 training images through AlexNet every second. Despite these high processing rates, with large datasets, training times for complex neural networks can still take days to train with a single GPU.</mark> 

## Slide 4: VGG Networks 

<mark>This slide briefly details the VGG family of networks. As we can see in the diagram, the VGG-16 (16layer architecture) is quite similar to AlexNet, consisting of convolution layers, pooling and fully connected layers. As can be seen in the diagram for VGG-16, each convolution block is made up of a cascade of 3 x 3 convolution layers. Thus, there are 13 convolution layers in total as opposed to 5 in AlexNet. The maximum number of channels also reached 512 in this architecture. The VGG networks are deeper than AlexNet and contain far more parameters. A key difference between the structure of VGG vs AlexNet is the use of the 3 x 3 convolutions. The authors determined that the receptive field of back-to-back convolution is equivalent to a larger convolution, but these operations are less computationally expensive than the larger 11 x 11 and 5 x 5 convolutions used in AlexNet. VGG networks also retain the fully connected layers at the end of the network. As we saw with Alexnet, these fully connected layers are the dominant source of parameters in the model. The increased numbers of parameters can lead to problems with overfitting during training, but does also lead to increased accuracy on ImageNet.</mark> 

## Slide 5: Model Zoo 

<mark>Figure (a) shows a graph of the computational operations vs accuracy of many neural networks on the IMAGENET dataset. The accuracy is measured by the Top1 accuracy, which refers to the percentage of time the highest-class probability output by the network, corresponds to the correct label. The diameter of the circles indicates the approximate number of parameters in each network. As we can see, the AlexNet network is in the bottom left-hand corner of the graph. It is not particularly accurate and does not have a large computational demand, but significantly does have a large number of parameters. We can also see the VGG family of networks with increased accuracy, increased computation and extremely large parameter sizes. As we have seen both AlexNet and VGG use large fully connected layers at their outputs to increase the total number of parameters which helps enable high accuracy of the networks. The use of the large number of parameters makes VGG in particular unsuitable to run on mobile devices with small memory. Also during training fully connected layers demand a high memory bandwidth and cause slow training on GPUs. Motivated by these concerns, research quickly turned to finding novel network architectures that could eliminate the use of fully connected layers. This was achieved by developing deeper architectures that contain more processing in the convolution layers, that learn better representations of the data and in turn allow better discrimination of the classes. In this lesson we will look at the concepts and ideas behind the Inception architecture and in the next lesson we will focus on residual structures which have proven to be a robust way to train deep neural networks.</mark> 

## Slide 6: Network in Network 

The network in network structure was proposed by Lin in 2014, this is a different approach to forming a convolutional neural network than the traditional convolution with activation we have discussed previously. In the network in network structure the convolution kernel is replaced by a small Muti-layer perceptron which is just a small fully connected network. This small network is still applied in a convolutional type manner across the input feature map. The rationale for doing this is that convolution is a linear operation, and the representational power of the features produced may be low. This results in features being not easily discriminated and drives the requirement for large output FC layers in traditional CNNs like AlexNet and VGG to determine the classes. By adding small FC layers directly into the convolution and increasing the number of parameters locally, the learned features can have a greater representational power and the classes more easily discriminated. In this case the output FC layers can be replaced with just one global average pooling layer, which we will discuss in the next slide. The network in network was originally developed in 2013 as a small scale network for use with MNIST and CIFAR datasets, however the concept was used in the Inception architecture which was the winner of the 2014 Large Scale Visual recognition challenge. We will shortly discuss the inception architecture in this lesson. In the inception architectures using the network in Network concept the  small FC layers are replaced by equivalent 1 x 1 convolutions as it is much more computationally efficient. 

## Slide 7: Global Average Pooling 

Also in the Network in Network paper the Global average pooling layer is proposed as an alternative to dense layers acting as a classifier in CNNs. Dense layers contribute greatly to the parameter count in neural networks and are prone to overfitting, requiring regularisation such as dropout to train properly. As mentioned on the last slide global average pooling should only replace dense layers when the convolution layers of the network are capable of extracting more abstract features or the network is deeper, which has the same effect. The global average pooling layer shown in figure (a) automatically pools a feature map of any size down to a size of 1. A 1D array results with one element of the array corresponding to each feature map.  Typically the global average pooling layer is followed by a dense layer with softmax, which converts the values to class probabilities. 

## Slide 8: Inception Principles 

<mark>The Inception architecture departs from the sequential convolution and pooling layer structure of AlexNet and VGG. It has an alternative structure based on a theoretical result by Arora which states that a data distribution can be represented by a large sparse network. Figure (a) compares a dense and a sparse network, the sparse network has fewer connections and therefore fewer parameters and a lower computation cost. Typically the CNNs networks that we train are dense, but many of the learned parameters could be close to zero and are therefore redundant. A lot of computation is therefore wasted in many CNN architectures. However modern GPUs are designed for dense computation and can’t easily take advantage of the computational savings of sparse networks even if we can find and remove the low value parameters from an existing network. The authors of inception were motived to find an architecture that could be processed using standard dense layers like convolution but that would more closely resemble this theoretical optimum sparse network. In order to construct the dense equivalent of this ideal sparse network, the authors followed the statement from the paper by Arora, which states we should use a "Layer-by layer construction in which one should analyse the correlation statistics of the last layer and cluster them into groups of units with high correlation. These clusters form the units of the next layer and are connected to the units in the previous layer". As shown in figure (b) a 1 x 1 convolution applied across a feature map can easily find correlations across feature maps.  3 x 3 and 5 x 5 convolutions can find correlations</mark> 

<mark>across slightly wider regions. These are used as the main computations in the Inception module discussed on the next slide.</mark> 

## Slide 9: Inception Architecture 

<mark>Each inception module is considered to be a "network within a network", which we have previously discussed as a way to improve the representation power of the entire neural network with embedded networks in each layer. The inception module itself, as shown in figure (a), contains parallel convolution stages with different kernel sizes, as well as a pooling layer. The different size convolution kernels allows correlations to be obtained between wider spaced pixels or neurons of the input to the layer. The outputs of the convolutions are concatenated together into one larger output feature map containing all the information about correlations. The max convolution size is limited to 5 x 5 as large convolution kernel sizes greatly increase computation. A parallel pooling path is also included by the authors, due to the success of pooling in many other architectures. A problem with this structure is that 5 x 5 convolutions can occur deep in the network; this would be computationally very expensive where there are many input feature maps. For this reason, the inception architecture as shown in Figure (b) introduces "bottleneck" layers of 1 x 1 convolution ahead of the 3 x 3 and 5 x 5 convolutions to reduce the amount of computation.</mark> 

## Slide 10: Auxiliary Classifiers 

<mark>The version of the inception architecture known as GoogLeNet that was submitted to the ImageNet completion is a 22 layer deep architecture. At the time of publication, this was the deepest known CNN architecture. A global average pooling layer is used to convert the last convolution output to an input suitable for the final fully connected layer. Dropout is also used during training with the fully connected layer. The GoogLeNet architecture can be considered to be both deep and wide, with the width arising from the number of parallel convolutions. Note that GoogLeNet used auxiliary outputs, which are used only during training. This approach helped avoid vanishing gradients during training; the multiple outputs mean we effectively have a superposition of networks of different depths. A joint loss function was used to combine the auxiliary outputs during training. These outputs are removed when the network is used for inference.</mark> 

## Slide 11: Inception Performance 

Overall the GoogLeNet network used 12 times less parameters than Alexnet and achieved better performance. The model is also significantly smaller than VGG networks. Later versions of the Inception architecture have been published with further enhancements including the use of batch normalisation, which we will see in the next lesson. Also in later versions the 5 x 5 convolutions are replaced with sequential 3 x 3 convolutions to reduce computation and convolution with a stride of 2 is used to reduce spatial size in the inception modules. The performance of later versions of Inception are competitive with the best performing architectures for image classification at the cost of increased computation.
