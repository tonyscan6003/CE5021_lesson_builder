## Slide 2: Deep Learning 

Deep learning has become the dominant approach to solving machine and computer vision tasks in recent years. The success of deep learning has relied on a confluence of technologies, the availability of large amounts of training data due to the big data revolution, the development of deep architectures and the algorithmic tools such as gradient descent and backprogation required to enable training of neural networks, and finally the availability of high performance parallel computing in the form of GPUs to carry out the training process in a reasonable time. Deep learning has found applications in many vision tasks, including object detection, pose estimation and medical image diagnostics. Some important problems may be encountered when deploying a deep learning solution to a new task or image domain. A common problem is that there is insufficient data in the new domain to train a model to the required degree of accuracy, this often occurs with specialised image domains such as medical images. Secondly even if enough data is available the computational cost and resources to train a deep learning model may be seen as expensive or technically difficult. Transfer learning has emerged as a very popular solution to these two problems, and is extensively used to train deep neural networks in many machine and computer vision tasks. 

## Slide 3: Transfer Learning 

Transfer learning uses the idea that a deep neural network can be partitioned into feature extractor and a classifier parts, this is shown in figure (a). As we saw in the lesson on visualisation, the convolutional layers in a neural network respond to image features, with earlier layers in the network responding to simple image features, such as lines, edges and blobs. While deeper layers respond to more specific and complex features. With a large training dataset such as ImageNet, the convolutional neural network is considered to have learned many generic image features. In transfer learning the pre-trained convolutional layers of the network may be re-used in a new application as shown in figure (b). In the simplest case, the pre-trained convolution layers are used a fixed feature extractor and only new classifier layers are learned, however fine tuning of the feature extractor can help performance and usually both this and the new classifier are trained together. Transfer learning solves the problem of small amounts of data in the target domain, by using the generic features of the pre-trained convolution layers. It also helps to reduce the amount of computation required as the new system should converge quickly to the final accuracy. 

## Slide 4: Object Detection 

In the example shown on the previous slide, transfer learning was used to perform image classification with a new set of images with different classes. Therefore the image data has changed, but the vision task being performed was the same.  However transfer learning can also be used when both the data and the task being performed changes.  On this slide we will consider the case of applying transfer learning to object detection. We will assume again that we have a pre-trained 

feature extractor that has been trained on a generic dataset such as ImageNet. As shown in figure (a), when we apply a common image such as the cat to the feature extractor, certain feature maps in the last layers of the network will be activated. These feature maps will not be activated uniformly but the pattern of activation will contain spatial information about the location of the cat in the original image. This information from the feature extractor can be passed to a class predictor to output a class label, and secondly a bounding box predictor can be trained to predict the coordinates of the cat in the original image. Usually fine tuning of the pre-trained feature extractor is performed and the network is trained end-to-end. The target domain data for object detection must of course contain information about the location of objects in the training images, which usually limits the amount of training data. The limitation in training data often makes transfer learning necessary to train an object detector. 

## Slide 5: Should we always use Transfer learning? 

Having understood the principles of transfer learning, we might ask the question if we should always use transfer learning when developing applications in new image domains? In general using a pretrained network, where the pre-training is done on the image classification task with ImageNet has become standard practice for training deep neural networks on vision tasks. As we have mentioned already, the use of transfer learning is key to training new applications when we are limited by either data or computation. Given the widespread adoption of transfer learning, many recent academic publications have sought to verify the principles behind transfer learning and challenge some assumptions that designers of neural networks have been making about transfer learning. The 2018 paper by He at al, makes some important observations. Due to the popularity of using transfer learning for complex vision tasks such as object detection, many designers have assumed that object detection networks can’t be trained from scratch. However the authors show that it is possible to train most networks for tasks like object detection from scratch, and these networks do not need highly specialised architecture to learn. The authors also confirm that convergence to high accuracy occurs faster with pre-training, however the accuracy achieved is not any better than can be achieved by training from scratch. But it will take longer to achieve this accuracy. Figure 1. Reproduced from the paper by He, shows training curves with the same data for a pre-trained network (grey curves) and also a network trained from random values (purple curves). It can be seen the pre-trained network converges more quickly, but final accuracy is the same over a long period of training. The authors also point out that accuracy achieved when training from scratch may fail to match the accuracy when using transfer learning, if the dataset is very small. A final observation made by the authors is that the total time to train any model with transfer learning is long when the pre-training phase is considered. Obviously by using transfer learning with a pre-trained model in our application, we take advantage of the computational time and cost used to initially train the model. 

## Slide 6: Transfer learning and specialised Tasks? 

Transfer learning is often used for training networks in specialised domains such as medical images. However as discussed by Raghu et al, transfer learning may not work as well when there is a big difference between images in the target domain and the data used for pre-training. This is often the case for medical images. In this paper the authors found that a randomly initialised and lightweight model with few parameters, that is trained from scratch may perform as well as a more complex model trained via transfer learning. In the table reproduced from the paper, it can be seen the very large Resnet 50 model, can be trained via transfer learning to achieve high accuracy on the diabetic retinopathy task. Consistent with results from the paper discussed on the previous slide, the same Resnet 50 architecture can be trained from scratch to achieve the same accuracy as with transfer learning. However the authors show some lightweight “CBR” architectures that achieve comparable performance to the ResNet 50 architecture on the diabetic retinopathy task, with far fewer parameters. All these architecture achieve poor results when trained in ImageNet, as they don’t have to complexity for that task, but are sufficiently complex for the diabetic retinopathy task. Many neural network designers may choose a complex network and deploy it to their task via transfer learning, without considering if a lightweight model is more suitable. The transfer learning approach is often only used, because of the ready availability of a model with pre trained weights. Finally in agreement with the paper discussed on the previous slide, transfer learning is very useful in the case where a larger model is required due to a complex task, but only limited data is available in the target domain. 

## Slide 7: Transfer Learning Recommendations 

On this slide we will summarise when we should employ transfer learning if we are training a neural network for a new application. We need to give consideration to the similarity of the source and target domains, the similarity of the labels and also the size of the source and target datasets. Using a pre-trained model and applying transfer learning may be the only possible solution when we have limited computation or limited target domain data. The most favourable case for transfer learning is when we have similar source and target domains and the source has a large dataset. In this case if the classes or objects are similar between the source and target, excellent performance can be achieved even without fine tuning the network. Secondly the accuracy achieved with transfer learning will likely be much better than the accuracy which can be achieved by training from scratch when the target dataset is small. With a large target dataset equivalent performance can be achieved with transfer learning and training from scratch, but transfer learning will save on training time.  If the source and target domains are less similar then fine tuning will be necessary to achieve good accuracy on the target domain. There is also a risk of overfitting the target domain if the target domain dataset is small, leading to worse performance than training from scratch. If the source and target domains are dissimilar as in the case of medical images, then equivalent performance can be achieved by training the network from scratch with a medium size dataset. With a very small target dataset transfer learning will perform slightly better than training from scratch. In deciding whether or not to use transfer learning for a given application, the availability of computational resources is another consideration. If computational resources are limited, then training from scratch may be impractical, so using transfer learning becomes a good option. As mentioned already using transfer learning can save training time, for example many state-of-the-art object detectors are quickly trained using transfer learning rather than attempting to train from scratch. 

## Slide 8: Pretrained Models 

In addition to being able to specify your own models, Keras also has an applications module, which contains many standard image recognition models, such as ResNet50, VGG16 and DenseNet. These models are pre-trained and are ready to use for image classification. They can also be used as basis for many machine vision applications with transfer learning. It is extremely simple to instantiate one of the pre-trained models in Tensorflow, the code snippet on the slide is taken from the Tensorflow Transfer Learning tutorial. In the example an instance of the MobileNetV2 is created, we note that we can define an “input_shape”, which allows the size of the model tensors to be calculated. Also important is the parameter “include_top” which accepts a boolean value, when set to false, the fully connected classification part of the network is removed leaving the feature extraction part only. We can choose to freeze the layers of the feature extraction part and just train new classification layers or fine tune the entire network.
