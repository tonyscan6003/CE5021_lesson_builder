## Slide 2: Object Detection with Deep Learning 

The object detection task is more challenging than image classification. In image classification we assign one label to the entire image, in object detection it is necessary to localise multiple objects of different classes within an image. The network for object detection will predict a class for each object and also predict a bounding box around the spatial extent of the object.  In the last section of the course we discussed deep learning based image classifiers, and a pre-trained image classifier provides a good starting point for an object detection system. We can naively turn the image classifier into an object detector by using the basic sliding window approach. As shown in figure (b) we can send the region of the image under the window to the image classifier. If a valid class is identified by the classifier, we can assume there is an object corresponding to a particular image class within in the region occupied by the window. The window moves around the image exhaustively checking the entire image for objects. This approach is too computationally expensive and slow when the classifier is a large model like a neural network. With a large high resolution image, there could be thousands of window positions to classify. With the sliding window approach, in order to detect objects in the image at different scales, an image pyramid will have to be used and this further increases the amount of computation. 

## Slide 3: Object Detection with Region Proposals 

As we have seen on the last slide the basic sliding window with a pre-trained image classifier is not a computationally efficient way to build an object detector, as it leads to too many calls to the image classifier. Ideally we want to reduce the number of candidate regions of the image that we search in for objects. The can be achieved with a Region proposal algorithm, that identifies regions of an image most likely to contain an object. For example in the image (a) we predominately search in the centre of the image for the objects. There are various approaches to region proposal algorithms, that we will see in the next lesson. However image segmentation turns out to be the most fundamental quantity to help in identifying regions occupied by objects, for example the image in figure (b) has been segmented which identifies the region of the image corresponding to the koala bear. This region can be passed to the image classifier in order to determine the class of the object. 

## Slide 4: Basic DL based Object Detection Proposals 

We can now build a deep learning based object detector by combining an image classifier with a region proposal algorithm as shown in Figure (a). The system will require some modification to the image classifier to be able to predict bounding boxes and labels for multiple objects. This approach was used by the very well known RCNN object detector, which was one of the first deep learning based object detectors published in the literature. We will discuss this system and the later more 

refined versions in more detail in a later lesson. Compared to the naïve sliding window approach, by including the region proposal algorithm, it reduces the amount of regions that we need to classify. Rather than having a fixed window size and requiring an image pyramid to detect objects at different scales, region proposal algorithms can also find regions containing objects of any shape or size in the image. A good quality region proposal algorithm is also important in reducing the number of false positives produced by the system, also the number of false negatives or missed objects can be reduced if the algorithm can propose regions around all the objects in an image. There are of course some obvious problems with this approach. Firstly the region proposal algorithm is trained separately from the image classifier, so we no longer have end-to-end training, which is what we want to achieve with deep neural networks. Secondly the regions proposed are of different shapes and sizes, corresponding to the scale of objects in image. As most neural networks are designed to accept fixed size inputs, a solution must be found to this problem. Finally we can see that the image classifier will end up operating on overlapping regions several times, this is inefficient. We will discuss all these problems and their solutions again in the later lesson on object detectors architectures. In the remainder of this lesson we will briefly discuss datasets for object detection and metrics used to compare the performance of object detectors.

## Slide 6: Object Detection Metrics. 

As we have mentioned already, a key function of an object detector is to estimate a bounding box around the objects in the images. The quality of a prediction can be measured using the Intersection over Union metric. As shown in figure (a) The Intersection over Union is calculated as the intersection area of the predicted and ground truth boxes divided by the union of the area of the two boxes. Ideally the predicted bounding boxes overlaps exactly with the ground truth, the IoU will be equal to 1 in this case and is lower for partial overlaps, reaching zero when the predicted box fails to overlap at all with the ground truth. A deep neural network based object detector will usually output a large number of predictions and some of these will not be valid. A confidence value is usually output along with the bounding box and predicted label. This confidence value signifies the probability that the bounding box contains a valid object, if the confidence is low then this prediction is ignored. The condition for determining if a prediction is a true positive, false positive or false negative is determined by using threshold levels for the confidence level and IoU. As seen in figure (b) we initially ignore any predictions with low confidence below the threshold T1. If the prediction has a high confidence above the threshold and the IoU is greater than the threshold T2, then a true positive is detected. If the prediction again has a high confidence above the threshold but now the IoU is less than the threshold T2, then a false positive is detected. Finally if an object is not detected by any predictions from the detector, then a false negative is produced. The selection of the threshold values of the confidence and IoU will affect the balance between precision and recall that we observe from the detector. 

## Slide 7: Precision Recall Curve 

In the object detection task, we don’t use the concept of a true negative prediction. This is because most of the image is background which could be interpreted as True negative examples, thus the number of true negatives would be far, far greater than the number of true positives, giving a very imbalanced set of data. Therefore only the precision and recall metrics, that don’t use true negatives are used as metrics for the object detection task. The precision is defined as proportion of positive predictions that are actually correct and is calculated as the number of true positives divided by the sum of the true positives and false positives. The recall is defined as the proportion of positives correctly identified and is defined as the true positives divided by sum of the true positives and false negatives. Depending on the selection of the confidence threshold then the balance of precision and recall will be effected. In figure (a) we can see the difference between setting a high or low confidence threshold level for the predictions. With a high confidence threshold, only the best quality predictions are retained, this avoids false positives but results in high numbers of false negatives as objects are missed when predictions are rejected for being below the confidence threshold. Therefore with high confidence threshold, the detector will have high precision but low recall.  If the confidence threshold is set to a low value then most of the predictions produced by the object detector are retained. This will result in an increase in false positives, but a reduction in the number false negatives, therefore the precision will reduce and the recall increase. Figure (b) shows the trade off curve between precision and recall for a binary object detector as the confidence is varied from high to low. In this example the IoU threshold was fixed. We can produce similar precision recall curves by varying the IoU threshold, a high IoU threshold will increase precision and a low IoU threshold will increase recall. As we will shortly see it is important when comparing object detectors that precision recall curves are obtained with the same IoU threshold. 

## Slide 8: Interpolating PR Curve 

In actual object detectors the precision recall curves produced are often zig –zag in shape as shown in figure (a). In an actual precision recall curve, as the confidence is reduced the recall increases monotonically while the precision moves up and down. With an ideal detector we want the precision to remain high as recall increases. In order to compare object detectors we can use the area under the curve as a measure of how well precision stays up as the recall increases with reducing confidence. As the curve has a zig-zag shape it is necessary to interpolate it as shown in figure (b) before the area under the curve can be estimated. ## Slide 10: Object Detection Errors 

As we observed on the last slide we get poor average precision performance on particular classes. We would like to be able to understand exactly why poor AP is being achieved for specific categories or across all categories. The types of errors impacting average precision have been investigated in the paper by Hoiem et al. The authors determined that false positive errors were firstly composed of localisation errors where the bounding box around correctly classified objects is inaccurate, two examples of this are shown in the figure. Secondly in similarity error, objects are misclassified as similar objects from different classes. As shown in the figure this can easily occur for similar objects such as animals. The final type of false positive occurs when an object is falsely identified from a pattern in the background of the image. False negatives typically occur due to object size. Many object detectors have difficulty detecting small objects in images, as well as identifying partially obscured objects and objects that have been truncated or cut off by the border of the image. 

## Slide 11: Evaluating Errors with AP 

On the last slide we briefly discussed sources of error in object detectors, it is difficult to determine the primary sources of error by visually inspecting images produced by the object detector. The COCO dataset provides as part of it’s API, an analysis function to help assist in failure diagnosis. The analysis function produces a series of precision and recall curves as shown in the example of figure (a) with 

gradually more relaxed conditions for evaluating precision and recall on each iteration. This enables identification of the sources of failure in an object detector when evaluated on the COCO test data. The test conditions start with a high threshold for IoU, then a reduced IoU threshold. Next errors due to localisation are removed, followed by the similarity errors, etcetra.  Each time the errors are removed we can see the precision recall curves shift to the right, which implies a greater area under the curve and hence better average precision. The amount the curve shifts to the right each time gives an indication of how much the average precision is improved by the removal of a particular error source. For example we can see that removing localisation errors (the blue colour) had a much greater impact than removing the similarity errors (red colour). These curves allow us to identify what to focus on when trying to improve the object detector network. In the example shown in figure (a), it is clear that focus should be on removing, background errors, localisation errors and false negatives. 

## Slide 12: Data Augmentation for Object Detection 

One final point on object detection is the use of data augmentation during training. We might use data augmentation to further improve the precision of a system or it may be necessary to prevent overfitting in cases with limited data. In order to perform augmentation of images, we can apply photometric operations such as equalisation, contrast or brightness changes. We can also apply geometric operations such as rotation, shearing, translation or flipping. It is important to note that many geometric transformations will also require the bounding box coordinates for the object to be modified, which is an extra complication when applying data augmentation to object detection. The photometric and geometric operations can either be applied to the entire image or just to the region including the bounding box. As shown in the figure, combinations of operations can also be applied. For different applications there may be an optimal policy or combination of operations, this is discussed in the paper by Zoph. Unfortunately object detection specific augmentation is not available in tensorflow, operations are available that will transform the image, but bounding box coordinates must be manually updated. Many object detection systems use simple policies, such as image scaling, translating the image or using random crops as these are simpler to perform than operations such as rotation and shearing.
